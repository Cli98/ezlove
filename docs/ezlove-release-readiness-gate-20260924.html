二、五道门禁逐条核查

G1 · 功能与安全

✅ 达标
  • 四类"越权访问"高危漏洞（陌生人乱发内容、看老人状态、跨社区改数据）已全部修复并加测试固化。
  • 核心列表打不开、"今日"时间算错、后台超时面板失效等回归问题已全部修好。
  • 小程序首页/历史/提醒、后台老人/事件列表的显示问题已修复。
  • 后端自动化测试 53 项全部通过，覆盖安全、核心流程、时间口径、限流等。

G2 · 合规与隐私（法律 + 微信审核双要求）

⛔ 未过
  • 登录页现在只有一行"登录即代表同意…"的静态文字，没有真正能点开看的《隐私政策》《用户协议》，也没有"必须勾选同意"和"可以撤回"。
  • 本产品会记录老人的位置、健康、作息等敏感信息，属于法律高敏感场景，协议文本需要法务把关，不是前端加个页面就行。
  • 结论：对外发布前必须有正式的隐私政策页 + 主动勾选 + 可撤回入口。

G3 · 微信小程序对外发布链路

⛔ 未过
  • 域名 + HTTPS：线上后端目前只有一个 IP 地址（http://118.178.169.245），没有域名、没有加密（HTTPS）。微信要求正式/体验版必须用"已备案域名 + HTTPS"，这一步直接卡住对外。
  • 未读提醒送不到：产品的核心卖点是"老人没看 → 提醒子女微信"，但微信订阅消息模板还没申请、没配置，现在这条提醒是"哑火"的。
  • 老人直达没做好：还差"微信卡片点一下就能看"的分享直达链路，现在老人要好几步才能看到内容。
  • （好消息：小程序名称、AppID、微信服务类目、主体备案此前已通过审核。）

G4 · 服务器运维底座（敢不敢承接真实数据）

⛔ 未过
  • 没有数据备份：全项目零备份实现，老人数据一旦服务器出问题就是不可挽回的事故。
  • 服务不会自愈：服务器重启后，后端服务不能保证自动恢复。
  • 上传的图会丢：老人/子女上传的照片没有做持久化存储，系统一重建就全没了。
  • 线上配置和代码库不一致：直接按代码库重新部署会失败，需要先核对同步。

G5 · 真实数据与真机验收

🟡 进行中
  • 接口层联调已完成：小程序与服务端的六大流程（登录、绑定、发牵挂、老人查看、提醒处理、个人中心积分）端到端验收 38/38 全绿。
  • 真机端到端联调进行中：受限于 G3（还没有 HTTPS 域名），手机上的完整体验验收还没跑完。
  • 真实老人名册导入未完成：现在用的是演示/模拟数据，正式绑定关系模型、试点家庭导入、工作人员培训还没落地。

五、关键路径与时间线（把"审批日历"和"写代码"分开算）

决定"最早哪天能对外"的，不是我们写代码的速度，而是外部审批要多久。红色节点是审批日历（不可压缩，须今天启动），橙色是工程冲刺。
【今天启动 · 审批线】 域名购买 → ICP 备案接入 （1–2 周起）
备案通过后 → SSL 证书 → 服务器开 HTTPS(443) → 微信后台配置合法域名
【今天启动 · 审批线】 微信公众平台申请"订阅消息模板" （数天–1 周）
审批通过后填模板 ID → 打通"未读提醒"送达
【今天启动 · 法务线】 隐私政策 / 用户协议正文 （法务把关）
【工程第 1 周】 运维底座：每日备份 + 恢复演练 + 服务自愈 + 上传文件持久化 + 配置同步
【工程第 2 周】 隐私政策页 + 勾选撤回、订阅模板接入联调、老人卡片直达、后台文案整改
【工程第 3 周】 真实数据导入隔离、首批家庭绑定、体验版真机全链路验收

建议节奏（两步走）：先让管理后台对外（社区工作人员用，无微信审核依赖，最快产生价值）；小程序在满足"域名 + 隐私 + 订阅模板"三门禁后提审发布。

七、对外发布 Go / No-Go 核对清单

  • 功能与安全 —— 越权修复、核心流程回归、后端 53 项 + 联调 38 项测试全绿
  • 已备案域名 + HTTPS —— 微信后台配置合法域名，体验版/正式版能连线上
  • 订阅消息模板已接入 —— "未读提醒"能真实送达子女微信
  • 隐私政策 / 用户协议 —— 可查看、可勾选同意、可撤回（法务过）
  • 老人卡片直达 —— 点微信卡片 2 步内看到内容
  • 运维底座 —— 每日备份 + 恢复演练 + 服务自愈 + 上传持久化 + 配置一致
  • 真实数据验收 —— 体验版真机全链路跑通；试点数据与模拟数据隔离
  • 合规文案 —— 三端无"监控/追踪/报警"，后台"告警"改为"提醒"
