## 二、管理员操作清单（含验收标准）

### 1. 每日数据库备份（含保留策略）

建议做法（管理员权限执行；容器名以实际为准）：

```bash
# 手动验证一次导出（不落盘，仅验证可导出）
docker exec ezlove-db-1 pg_dump -U postgres -d ezlove --format=custom > /dev/null && echo DUMP_OK

# 建议 cron（每日 03:30，保留 14 天；目录请按服务器既有约定调整）
# 30 3 * * * docker exec ezlove-db-1 pg_dump -U postgres -d ezlove --format=custom \
#   > /var/lib/ezlove-deploy/backup/ezlove-$(date +\%F-\%H\%M).dump \
#   && find /var/lib/ezlove-deploy/backup -name 'ezlove-*.dump' -mtime +14 -delete
```

**验收标准**
- [ ] `DUMP_OK` 输出正常（备份文件 > 1MB）
- [ ] 连续 2 天在目标目录可看到新备份文件
- [ ] `pg_restore --list <备份文件>` 可正常列出内容

### 2. 恢复演练（一次性，必须留证据）

```bash
# 1) 取最近备份文件
ls -lt <备份目录>/ezlove-*.dump | head -1

# 2) 恢复到临时库（不改动生产库）
docker exec ezlove-db-1 createdb -U postgres ezlove_restore_test
docker exec -i ezlove-db-1 pg_restore -U postgres -d ezlove_restore_test --no-owner < <备份文件>

# 3) 抽查（行数应接近生产库）
docker exec ezlove-db-1 psql -U postgres -d ezlove_restore_test -c \
  "select (select count(*) from users) users, (select count(*) from care_moments) moments, (select count(*) from alerts) alerts;"

# 4) 清理临时库
docker exec ezlove-db-1 dropdb -U postgres ezlove_restore_test
```

**验收标准**
- [ ] 演练记录（日期 / 备份文件 / 恢复耗时 / 抽查数字）归档
- [ ] 抽查行数与生产库接近（同一时点快照）

### 3. 服务自愈（重启自动恢复）

```bash
# 检查各容器重启策略（应为 unless-stopped 或 always）
for c in ezlove-backend-1 ezlove-admin-frontend-1 ezlove-db-1 ezlove-redis-1; do \
  docker inspect -f "$c => {{.HostConfig.RestartPolicy.Name}}" $c; done

# 检查 Docker 服务开机自启
systemctl is-enabled docker
```

**验收标准**
- [ ] 4 个容器 RestartPolicy 均为 `unless-stopped` 或 `always`
- [ ] `systemctl is-enabled docker` 输出 `enabled`
- [ ] 演练（择窗口）`systemctl restart docker` 后 5 分钟内 4 容器自动 Up、健康检查 200
      （注意：共享宿主机与教学系统共存，操作窗口需管理员评估）

### 4. 上传文件持久化（照片/视频不丢）

```bash
# 查看 backend 容器的挂载（重点看是否有宿主目录映射到 /app/static/uploads）
docker inspect -f '{{range .Mounts}}{{.Source}} => {{.Destination}}{{"\n"}}{{end}}' ezlove-backend-1
```

**建议**：宿主目录如 `/var/lib/ezlove-deploy/uploads`（或服务器既有约定目录）绑定到 `/app/static/uploads`。

**验收标准**
- [ ] `docker inspect` 可见 `/app/static/uploads` 的宿主映射
- [ ] 实测：小程序上传一张照片 → `docker restart ezlove-backend-1` → 图片仍可打开
- [ ] 实测：经 `ezlove-release deploy` 发布一次后 → 图片仍可打开

### 5. 配置一致性

固定基线（服务器 `/etc/ezlove-deploy/`，root 私有）与仓库对应关系：

| 服务器固定文件 | 仓库基线文件 | 关键约束 |
|---|---|---|
| backend Dockerfile | `backend/Dockerfile` | 发布包同名文件会被覆盖，以服务器版为准 |
| admin-frontend Dockerfile / nginx.conf | `admin-frontend/Dockerfile`、`admin-frontend/nginx.conf` | 子路径 `/ezlove/`、SPA 回退、`/api/` 反代 |
| 构建环境变量 | `admin-frontend/vite.config.js` | 依赖 `VITE_BASE_PATH=/ezlove/` 注入（防白屏回归） |

**验收标准**
- [ ] 每次发布后执行下方「发布后检查清单」全部通过
- [ ] 端口、挂载、网络、数据库凭证或构建方式如需变更：必须由管理员处理并同步通知开发方
